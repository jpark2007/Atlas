## 1. Scan removal (Mac only) — DESIGN DECIDED

Decisions (Drew, 09-02): batch removal, not one-click undo. Checklist UI. Clear-only for
`class_info`/`meeting_pattern`, no restore snapshot, no migration. Class page scan-history list,
Mac only. Canvas items never touched.

Brief:
- AtlasDB: `deleteScan(id:)` — deletes `tasks`/`events` where `scan_id = id AND canvas_uid IS NULL`
  for the given ids only (client passes the checked ids), then the `syllabus_scans` row. Also
  `scans(for projectID:)` list query if not present. Reference the `ScanRecord` model.
- AppState+School: `removeScan(_:keeping:)` that removes the checked items from local state and
  DB, awaits DB before mutating state (same rule as `recordScan`), clears `classInfo` and
  `meetingPattern` ONLY if the scan wrote them (ScanRecord flags if stored; otherwise offer a
  checkbox "Also clear class info written by this scan").
- UI: `ClassHubSection` gains a "Scans" card: rows = date · file/paste label · N items · Remove.
  Remove opens a sheet listing that scan's items; pre-checked = untouched since import,
  pre-UNchecked = `done == true` or `updated_at > created_at` (tasks have no created_at — use the
  scan's `created_at` as the baseline). Confirm button: "Remove N items".
- Tests: AtlasCore pure function that partitions items into touched/untouched given a scan
  baseline; AtlasDB call shape.
- Verify: gates + Drew's visual pass. iOS: none.
